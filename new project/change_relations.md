# Relations Module — Design and Implementation Notes

This document covers the design decisions, analysis, and implementation of
`src/relations.py` — the module responsible for identifying relationships
between equations within the same paper.

---

## What the relations field contains

The `relations` field for each equation is a dict keyed by every other equation
number in the same paper.  Every pair is always emitted (including `"none"`
pairs) so downstream consumers do not need to check for missing keys:

```json
{
  "2": { "grade": "strong",    "description": "The first term of Eq. (2) is the deflection signal..." },
  "3": { "grade": "potential", "description": "shares symbols: H, omega" },
  "4": { "grade": "none",      "description": "" }
}
```

Each entry has exactly two keys:

| Key | Type | Values |
|---|---|---|
| `grade` | string | `"strong"`, `"potential"`, or `"none"` |
| `description` | string | Verbatim sentence or deterministic template; empty string when grade is `"none"` |

All descriptions are either extracted verbatim from the paper's text or filled
from a fixed template using extracted data — never generated by a model.

---

## Why extraction only (no generation)

Same constraint as `meaning.py` and `symbols.py`: the project rules forbid
text generation at runtime.  All relation evidence is derived purely from the
paper's own text and the symbol sets produced by `symbols.py`.  No inference,
no LLM calls, no external resources.

Deterministic string templates (e.g. `f"shares symbols: {', '.join(shared)}"`)
are permitted because they are mechanical formatting of extracted data, not
novel natural-language prose.

---

## Four signals and grading

Relations are determined by four signals computed for each ordered pair
(A, B) where A is the equation being annotated and B is every other equation
in the same paper.

### Grading rule

- **`"strong"`** — signal 1 (cross-reference) **or** signal 3 (derivation cue)
  fired.  The relationship is *stated in the paper's text* by the authors —
  authorial, verifiable evidence.
- **`"potential"`** — no explicit textual link found, but signal 2 (Jaccard) **or**
  signal 4 (semantic similarity) fired.  Structural or semantic evidence only
  — inferred rather than stated.
- **`"none"`** — nothing fired.

Strong beats potential: if a cross-reference is found, the grade is strong
regardless of whether Jaccard or SBERT also fire.

---

### Signal 1 — Cross-reference (strong)

**Definition:** A's `context_before` or `context_after` contains an explicit
reference to B's equation number, e.g. `"Eq. (B)"`, `"equation (B)"`, `"(B)"`.

**Pattern** (reused from `meaning.py`'s `_EQ_CITE_RE_TMPL`):

```
(?:eq(?:uation)?s?\.?\s*)?\(\s*{N}\s*\)
```

**Sentence extraction:** The citation pattern is searched over the full
context string; the sentence around the match is then extracted by walking
left and right to the nearest `.!?` boundary.  Pre-splitting is deliberately
avoided because the sentence-splitter regex fires at `"Eq. (N)"` — the `.`
in `"Eq."` followed by a space-paren pair — which would fragment the very
sentence we need to return.

**Description:** Verbatim sentence containing the citation, truncated to
200 characters.

**Example:**
```
A context_after: "The first term of Eq. (2) is the deflection signal."
→ A~B grade = strong
  description = "The first term of Eq. (2) is the deflection signal."
```

---

### Signal 2 — Jaccard symbol overlap (potential)

**Definition:**
```
J = |A.symbols.keys() ∩ B.symbols.keys()| / |A.symbols.keys() ∪ B.symbols.keys()|
```
Fires when `J >= JACCARD_MIN` (constant = 0.30).

Symbol keys without backslash (e.g. `"H"`, `"omega"`) from `symbols.py` are
used.  Only symbols that passed `symbols.py`'s confidence gate are counted —
garbage symbols from the dependency fallback do not drive links.

**Description:** `f"shares symbols: {', '.join(sorted(shared))}"` — a
deterministic template listing the shared keys alphabetically.

**Why Jaccard instead of raw overlap count:** Jaccard normalises by the union
size, so two equations each with ten symbols and one shared key score 0.05
(no link), while two equations each with two symbols and one shared key score
0.33 (potential link).  Raw count would treat both identically.

**Example:**
```
A.symbols = {"H": "Hamiltonian", "T": "kinetic energy", "V": "potential"}
B.symbols = {"H": "Hamiltonian", "V": "potential", "E": "energy"}
Jaccard = |{H, V}| / |{H, T, V, E}| = 2/4 = 0.50 >= 0.30
→ grade = potential
  description = "shares symbols: H, V"
```

---

### Signal 3 — Derivation cue words (strong)

**Definition:** A's context contains a derivation-cue phrase **and** a
reference to B's equation number within the same sentence.

**Cue phrase list** (constant `_DERIVE_CUES`):
```
substituting, inserting, derived from, follows from,
combining, plugging, yields, into eq, using eq
```

Both conditions must be satisfied in the same sentence — a cue word alone
(without a citation of B) does not fire.

**Description:** Verbatim cue sentence (same extraction approach as signal 1),
truncated to 200 characters.

**Why this is "strong":** A sentence that both names B's number and contains
a derivation verb is direct authorial evidence of a logical dependency between
A and B.  It is not inferred — the author wrote it.

**Example:**
```
A context_before: "Substituting Eq. (1) into the Hamiltonian we obtain the result."
→ A~B grade = strong
  description = "Substituting Eq. (1) into the Hamiltonian we obtain the result."
```

---

### Signal 4 — Semantic similarity (potential)

**Definition:** Cosine similarity between the encodings of A's and B's
meaning sentences (falling back to context text if meaning is empty)
is >= `SBERT_MIN` (constant = 0.50).

**Encoder used:** SBERT `all-MiniLM-L6-v2` (sentence-transformers library).
SBERT is used as a pure encoder — it maps text to a fixed-size vector.  No
text is generated.  If sentence-transformers is unavailable, falls back to
TF-IDF cosine with threshold `TFIDF_MIN = 0.60`.  If scikit-learn is also
unavailable (e.g. DLL load error in the GPU lab environment), a built-in
pure-Python TF-IDF cosine is used — no external dependencies required.

All equations in the paper are encoded in a single batched call for
efficiency.

**Description:** `f"semantically similar (cosine={score:.2f})"` — a
deterministic template.

**Why SBERT over TF-IDF only:** SBERT captures meaning beyond keyword overlap.
"The wave function satisfies" and "ψ obeys the eigenvalue equation" get
similar SBERT vectors; TF-IDF would rate them as unrelated because they share
no words.

---

## Two-pass design in main.py

All four signals require data that is only available after all equations in the
paper have been fully processed.  Signal 2 needs the symbols dicts of all
equations; signal 4 encodes the meaning strings of all equations.

**Pass A (per equation):** `meaning.py` and `symbols.py` are called for each
equation.  Context fields (`_ctx_before`, `_ctx_after`) and meanings/symbols
are stored in a working dict `paper_build`.

**Pass B (per paper):** `compute_all_relations(paper_build, eq_audits)` is
called once.  It encodes all equation texts in one SBERT batch call, then
iterates all pairs.  The context fields are stripped from the final output
after this pass.

This replaces the previous two-method design (`extract()` per equation +
`compute_shared_symbols()` per paper), which could not produce grades or
descriptions because it lacked access to meanings and symbols at citation
time.

---

## Audit trail entries

One entry is logged per pair (A, B) regardless of grade:

```
relations: eq (1)~(2): grade=strong, signals=['crossref'], evidence='The first term of Eq. (2) is...'
relations: eq (1)~(3): grade=potential, signals=['jaccard=0.50'], evidence='shares symbols: H, V'
relations: eq (1)~(4): grade=none, signals=[], evidence=''
```

The `signals` list names every signal that fired, with its score where
applicable.  This lets a grader verify that the grade came from a specific
pattern in the paper's text.

## Design decisions

### Why emit all pairs including "none"?

The assignment spec example explicitly includes a `"grade": "none"` entry.
Emitting all pairs makes the output shape fully predictable — downstream
consumers do not need to handle missing keys.  It also makes the "none" rate
measurable, which is useful for the report's quality section.

### Why is cross-reference "strong" but Jaccard only "potential"?

A cross-reference is an explicit authorial claim: the author wrote "Eq. (2)"
in the context of equation (1) and thereby asserted a link.  Jaccard overlap
is structural evidence — two equations that share variables are likely related,
but the author did not say so.  The grade hierarchy reflects this epistemic
difference.

### Why sentence-around-match instead of pre-splitting for verbatim excerpts?

The sentence splitter `(?<=[.!?])\s+(?=[A-Z\(])` fires at `"Eq. (2)"` because
the `.` in `"Eq."` followed by a space and `"("` matches the pattern exactly.
Pre-splitting therefore fragments `"...of Eq. (2) is..."` into `"...of Eq."` and
`"(2) is..."`, losing the citation context.  Searching the full string first
and then walking outward to punctuation boundaries avoids this entirely and
produces a clean, complete sentence.

### Why is within-paper the only scope?

Cross-paper symbol sharing is not meaningful — `H` is the Hamiltonian in one
paper and the Heaviside step function in another.  Within-paper definitions
constrain what each symbol means in a consistent way.

### Why use symbol keys, not full definitions, for Jaccard?

Two definitions for the same symbol might read `"total Hamiltonian"` in one
equation and `"Hamiltonian of the system"` in another — identical quantity,
different phrasing.  Key matching (`"H" == "H"`) is exact and reliable; string
comparison of definitions would produce false negatives.

---

## Limitations

- **Cross-reference only captures explicit numbered citations.** If an author
  writes "plugging the previous result into..." without citing a number, the
  relation is not detected.

- **Jaccard depends on symbol extraction quality.** If `symbols.py` misses a
  definition, the symbol is absent from the key set and does not contribute to
  Jaccard.  Low symbol coverage → lower Jaccard scores → fewer potential links.

- **SBERT signal 4 requires a meaning or a non-empty context.** Equations with
  no extracted meaning and empty context receive an empty encoding; any cosine
  similarity against them is 0.0.

- **No cross-paper relations.** Both strong and potential relations are
  within-paper only.

- **Grading is symmetric for Jaccard and SBERT but not for signals 1 and 3.**
  A cites B does not imply B cites A; but if A shares symbols with B, then B
  shares symbols with A.  The output reflects this: `rels["A"]["B"]` and
  `rels["B"]["A"]` may differ in grade.
